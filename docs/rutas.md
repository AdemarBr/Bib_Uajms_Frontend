# Mapa de rutas y pantallas

Archivo de Figma: `Biblioteca UAJMS - Wireframe Iteración 3`, fileKey `a1bTBfFBoWOFxdfUamTrsd`, enlace https://www.figma.com/design/a1bTBfFBoWOFxdfUamTrsd/Biblioteca-UAJMS

Cada pantalla es un marco (frame) de 1440 px de ancho. La última columna da el id del marco (por ejemplo `9:7`) como enlace a ese marco. Con el MCP de Figma se usa el fileKey y el id del marco tal como aparece (`get_design_context` o `get_screenshot` con `nodeId: "9:7"`); en el enlace el id va con guion (`node-id=9-7`). Los ids entre paréntesis son modales, pestañas u opciones de esa misma pantalla.

Reglas:

- Columna «Tipo»: las rutas públicas no requieren sesión. Las de tipo «sesión» solo requieren sesión iniciada. Las de tipo «permiso» requieren el código indicado (guard `permisoGuard`); cuando se indican dos códigos con «o», basta con tener cualquiera de ellos.
- Columna «Acceso»: desde dónde se abre la pantalla. «menú»: opción del menú lateral. «desde PN.N»: enlace o botón de esa pantalla, porque necesita un registro elegido (no tiene opción en el menú; mientras está abierta, el menú marca como activa la opción de PN.N). «barra superior»: enlace de la barra superior.
- Un enlace o botón de una pantalla que abre otra se muestra solo si el usuario tiene el permiso de la ruta de destino (`*appTienePermiso`); si no, el nombre se ve como texto plano, sin enlace. La ruta de destino lleva igual `permisoGuard` (entrar por URL sin permiso lleva a `/`), y el backend responde 403 sin el permiso.
- La columna «Casos de uso» se obtuvo de las menciones a cada pantalla en los casos de uso y requerimientos del documento; los subcasos sin pantalla propia se asignaron a la pantalla donde ocurren.
- Sin sesión, una ruta protegida redirige a `/iniciar-sesion` (guardando la ruta pedida para volver después del login). Con sesión pero sin el permiso requerido, o con una ruta inexistente, se redirige a `/`.
- Los modales no tienen ruta: se abren dentro de su pantalla.
- P9.1 y P9.3 aceptan el parámetro opcional `?idReserva=N` cuando se llega desde el botón «Prestar» de P8.1 (RF8.8): la pantalla carga esa reserva y precarga el usuario y el ejemplar.
- Las rutas fijas se declaran antes que las que tienen parámetro (por ejemplo `/comunicacion/nueva` antes de `/comunicacion/:id`).
- Los botones de acción dentro de una pantalla (desactivar, asignar rol, confirmar, rechazar, exportar, responder, etc.) se muestran con `*appTienePermiso` según el permiso de su caso de uso en `docs/permisos.md`.
- El menú lateral muestra solo las opciones cuyo permiso tiene el usuario (los códigos llegan en el login).
- Tras un login correcto se vuelve a `returnUrl` (solo rutas internas) o, si no hay, a `/` (P.1 Home con sesión iniciada).
- Layout (RF1.2.10): sin sesión, las pantallas públicas (P.1 Home sin sesión, P6.1, P6.2, P11.1, P11.2) y el inicio de sesión (P1.1) usan el layout público, sin menú lateral (marco 9:7). Con sesión activa, **todas** las pantallas excepto P1.1, incluidas las públicas, usan el layout privado: barra superior con sesión (con «Catálogo» y «Tesis»), menú lateral filtrado por los permisos del usuario y pie. Referencia de Home con sesión: marco [396:132](https://www.figma.com/design/a1bTBfFBoWOFxdfUamTrsd/Biblioteca-UAJMS?node-id=396-132). Ese marco muestra el menú del Administrador general (todos los módulos): el menú no se copia fijo del marco; se usa el menú lateral de siempre (`opciones-menu.ts`) filtrado por permisos.
- Con sesión activa, entrar a `/iniciar-sesion` redirige a `/`.
- Cerrar sesión (confirmación «¿Cerrar sesión?») lleva a `/`, P.1 Home sin sesión (RF1.5.4). Solo una sesión vencida o una renovación rechazada (Iteración 5) llevan a `/iniciar-sesion`.
